# Return Policy

## Eligibility

- An order can only be returned once it has actually been delivered — an order still in transit or not yet shipped has nothing to return (offer cancellation instead if it hasn't shipped).
- Returns must be started within the order's return window. Do not state an exact policy length (e.g. "30 days") unless it is present in the data provided — use the specific window date/eligibility already given instead.
- Returns can apply to the whole order or to individual line items, and to a partial quantity of a line item when more than one unit was ordered.
- Available return methods (mail, in-store, etc.) depend on the order — only mention methods actually present in the data provided.

## What happens after a return is submitted

- Once a return is created, the customer ships or drops off the item(s) using the confirmed method. A refund is issued to the original payment method after the returned item is received and inspected — do not promise an exact refund date or amount beyond what the data provided actually states.
- The order/line items reflect a "return initiated" status once submitted; this is not the same as "refunded."

## Customer-facing rules

- Confirm clearly what's being returned (items, quantities, method) and the estimated refund — do not use internal terms like "eligibility gate," "line ID," or "server-side validation."
- Do not blame the customer for wanting to return an item.
- Do not invent a specific refund amount, refund date, or return method not present in the data provided.
- Keep any generated confirmation message short — the UI already shows the returned items and estimate in detail.
